# harness 0.2: closing the gaps with Hermes

Builds on `2026-11-19-harness-design.md`. The owner asked: "Close the gaps.
Subagents is a very useful feature everyone uses, make it good and actually
efficient." Gaps named in the comparison: research quality (page reading,
a browser, long conversations), MCP, skills, trading safeguards, sub-agents.
WhatsApp stays out of 0.2 (it needs a public HTTPS webhook and a Meta
business account; it belongs with the hosted service).

Stays: one Zig binary, std only, every action through the one gate, one
hash-chained log, secrets masked in all tool output, models only through
omnigate. No Elixir needed: sub-agents are threads.

## Sub-agents (`delegate`)

The agent hands out work as a list, run in parallel:

```json
{"tasks":[{"task":"Find the release date of Zig 0.17 and cite it","tools":["search","fetch"]},
          {"task":"…","tools":["search","browse"],"strong":true}]}
```

- Up to 8 tasks per call; at most `[agents] parallel` (default 4) run at
  once across the whole process (a shared counting limit); the rest wait.
- Each worker: a fresh conversation, a short worker prompt (do only this
  task, answer in at most ~300 words, cite links, say what failed), the
  owner's pinned instructions, nothing else from memory. Its tools are the
  ones asked for, minus `delegate`, `remember` and `skill_save` (one level
  deep, no writes to memory or skills). Default tools when none are named:
  search, fetch, browse, read_file, recall, skill.
- Model: `[model] worker_model` (default `claude-haiku`); `"strong":true`
  uses the main model.
- Limits per worker: `[agents] steps` (12), `[agents] tokens` (150000 input
  tokens summed over its calls), the parent turn's remaining time, and its
  answer cut to `[agents] answer_bytes` (4000).
- The parent gets one tool result: per task its answer, or why it ended,
  with steps and tokens. Never the worker's transcript.
- Same gate, same log (run label `chat/w1`, `chat/w2`, …), same stop flag:
  `/stop` stops workers. A worker's `ask` reaches the owner like any other;
  questions from parallel workers are asked one at a time.
- Efficiency: workers of one call share a page cache (a URL fetched or
  browsed by one is served to the others from memory); every request marks
  the unchanging prefix (tools, stable system text) for prompt caching, so
  workers after the first read the prefix from cache.

## Cheaper calls

- Prompt caching: the system prompt is sent as two blocks, stable (base
  prompt, skills list, pinned and top memory) with `cache_control`, then
  the changing part (time, recalled items). The last tool definition and
  the last message also carry `cache_control`, so each step of a turn
  reads the earlier steps from cache. omnigate passes these through and
  bills cache reads separately. Token counts for cache reads/writes are
  logged.
- Summaries instead of drops: when the conversation passes
  `conversation_bytes`, the oldest turns (all but the last 4) are replaced
  by a summary written by `memory_model`, kept as the first message. If the
  summary call fails, the old behaviour (drop) applies.

## Research

- `fetch` returns readable text: title, headings, paragraphs, lists,
  tables as rows, links as `[text](absolute url)`; scripts, styles,
  navigation, headers, footers, asides, forms dropped; main content taken
  from `<article>` or `<main>` when present. Long pages come in pages of
  `tool_output_bytes`: `{"url":…,"start":N}` continues; the reply says
  where the next page starts.
- `browse`: the same, but the page is rendered by a headless Chrome or
  Chromium first (for pages built by JavaScript). Found via `[browser]
  path` or standard install paths; a fresh throwaway profile each time (no
  cookies, no sign-ins); 30 s limit; stopped by `/stop`. Same gate rules as
  fetch (asks by default, a 24 h grant covers the host). Not found: the
  tool says so and suggests `fetch`.

## MCP

`mcp.ini` in the data folder:

```ini
[github]
command = npx -y @modelcontextprotocol/server-github
secret = GITHUB_PERSONAL_ACCESS_TOKEN:github   ; env var : stored secret name
money = place_order, cancel_order              ; tools that move money
amount = notional_usd                          ; field holding the amount
```

- stdio servers, newline-delimited JSON-RPC 2.0: `initialize`,
  `notifications/initialized`, `tools/list`, `tools/call`. Started when
  harness starts (and on `/reload`), each in its own process group in the
  workspace folder, with only PATH, HOME, LANG, TERM and its named secrets
  in its environment. A server that fails to start is reported and
  skipped.
- Its tools appear to the model as `server__tool`. Gate tool kind `mcp`,
  argument `server/tool {json input}`; default ask; a 24 h grant covers
  that tool with any input. Output masked like every tool's, capped at
  `tool_output_bytes`. One call at a time per server.

## Skills

agentskills.io format: `skills/NAME/SKILL.md` with frontmatter `name` and
`description`. The system prompt lists names and descriptions (capped);
`skill` loads one (allowed by default); `skill_save` writes one (asks by
default: it changes what the agent will do later). `/skills` lists them.

## Money safeguards

Tools listed under `money =` in mcp.ini are gate kind `money`:

- Always asked, every call: no "Allow 24 h" button, no grants, `allow`
  rules do not lift it (`deny` rules still apply).
- `[money] max_per_call` and `max_per_day` (in the amount field's units;
  0 = no cap) are hard limits checked before asking. The day's total is
  kept in `state/money`.
- Scheduled runs: refused unless `[money] scheduled = on`, and then still
  inside the caps, without asking (nobody can answer). This is the only
  way a money call runs unasked, and the owner must switch it on.
- `/dryrun on|off`: money calls are not made; the agent gets "dry run:
  would call …" instead. Logged like real calls.
- A money call missing its amount field is refused when any cap is set.
