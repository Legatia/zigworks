# harness-desk for macOS — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `harness-desk`, a small native macOS app ("harness" in the Dock) that finds harness through `state/desk.json`, starts it if asked, enters the desk by a one-time code, and shows `/desk` in a WKWebView with a non-persistent store, the bridge (badge, attention, reenter), navigation kept on `127.0.0.1:PORT`, the microphone for that origin only, and a menu for Start, Stop, Open at login, Reload and Quit; packaged as an ad-hoc signed universal `.app`, with a CI job and a release asset.

**Architecture:** `harness/desk-app/` is its own Zig package (own `build.zig`), so harness's build stays std only. All decisions are pure Zig, testable on any system: `args`, `home`, `deskjson`, `entry`, `alive`, `policy`, `bridge`, `commands`, `pages`, and `controller` (a state machine: events in, effects out). `main.zig` is the driver: it runs the controller on the main thread, does blocking work (liveness, entry, commands) on threads of its own and posts results back. `src/mac/desk.m` (one Objective-C file, ARC) is the Cocoa app, window, menu, WKWebView and its delegates, behind a C interface (`desk.h`) of a dozen calls and exported Zig callbacks. The Windows and Linux apps later add `src/windows/`, `src/linux/` beside `src/mac/` and reuse everything else.

**Tech Stack:** Zig 0.17.1 (std, libc), Objective-C with Cocoa and WebKit, macOS 12+; Python 3 for the fake harness (test only); `codesign`, `lipo`, `ditto` in packaging.

**Spec:** `docs/superpowers/specs/2026-11-24-harness-desktop-app-design.md` (binding: "The desktop app and getting in", "Constraints" — the desk app is the one exception to std only — "Who builds what"). The harness side (`/alive`, `/enter`, desk.json, the code file, `harness stop`, `harness autostart`, `harness open`) is platform/desk's; this plan builds against the spec and states the contract in its rulings.

## Global Constraints

- Zig 0.17.1 at `~/.local/zig/zig-aarch64-macos-0.17.1/zig`; private `--cache-dir` under the worktree's `.superpowers/`. Minimum macOS 12.0 (`os_version_min`, `LSMinimumSystemVersion`). One `.m` file, `-fobjc-arc -Wall -Werror`, built as headsound builds its `.m` (Xcode SDK paths from `std.zig.system.darwin.getSdk`, `b.graph.poisonCache()`).
- Files: only `harness/desk-app/`, `.github/workflows/`, the README's "Desk app (macOS)" section, this plan and the ledger. Nothing in `harness/src/`, `harness/build.zig`, `harness/tools/`.
- Names: the program is `harness-desk`; "harness" in the Dock, the menu bar and the window title; the page is `/desk`.
- Copy (CLAUDE.md): plain labels, no slogans. Fixed strings: "Set up harness first: run `harness init`."; "harness isn't running"; [Start harness]; "Connecting…"; menu "Start harness", "Stop harness", "Open at login", "Reload", "Quit harness".
- Window: content 1280×820 by default, at least 1024×700, its frame remembered (`setFrameAutosaveName`).
- Entry: write `state/open-request` (no secret); wait for `state/desk-code` (harness's: used once, valid 60 s); read it, delete it; load `http://127.0.0.1:PORT/enter?code=…`. `WKWebsiteDataStore nonPersistentDataStore`. Liveness `GET /alive` every 5 s while disconnected.
- Bridge, page → app only: `{"badge": N}` (Dock badge, empty at 0), `{"attention": "urgent"}` (`requestUserAttention` once), `{"reenter": true}`.
- Info.plist: `NSMicrophoneUsageDescription`, `NSAppTransportSecurity › NSAllowsLocalNetworking`.
- The harness suite stays green from `harness/`: `zig build test --summary all` and `-Doptimize=ReleaseSafe` (baseline at 4520a60 recorded in Done).
- Never the owner's real harness data: every launch on this Mac uses `--home` in a temp folder and the fake harness; the smoke app has its own bundle id and cleans its defaults afterwards.

## Review Focus

1. **harness comes back on another port** (its port was taken, it took the next and wrote desk.json): each liveness check re-reads desk.json, so the next entry and the navigation policy use the new port (`a_new_port_in_desk_json_is_used_from_the_next_check`, Task 4).
2. **Two entries racing for one code** (reenter pressed while an entry waits; a half-written code file): one entry at a time, a reenter during one is ignored, an empty code file is "not written yet" (`reenter_during_an_entry_is_ignored`, Task 4; `an_empty_code_file_is_not_a_code`, Task 2).
3. **Look-alike origins**: `http://127.0.0.1:PORT@example.com/`, `http://127.0.0.1:PORT0/`, `https://127.0.0.1:PORT/`, `http://localhost:PORT/`, `HTTP://127.0.0.1:PORT/` — only the exact origin stays in the window (`only_the_exact_origin_stays`, Task 3).
4. **harness stops while the desk is shown** (Stop from the menu, a crash): the window shows "harness isn't running" within two checks, not a dead page (`two_missed_checks_while_in_show_down`, Task 4; smoke step "stop").
5. **The app opened before harness ever ran**, then `harness init` and `harness run` in Terminal: the app notices desk.json appear and enters with no restart (`desk_json_appearing_is_noticed`, Task 4; smoke's first steps).

### Task 2: Entry and liveness

**Files:** create `src/entry.zig`, `src/alive.zig`.

**Produces:**
- `entry.request(io, home) !void`: deletes a stale `state/desk-code`, writes `state/open-request` = `pid N\n` (0600).
- `entry.take(io, a, home) !?[]u8`: reads `state/desk-code` (at most 1 KB), deletes it, returns it trimmed; missing or empty (being written) → null.
- `entry.wait(io, a, home, timeout_ms, poll_ms) !?[]u8`: `take` until a code or the time is up.
- `entry.enterUrl(a, port, code) ![]u8` → `http://127.0.0.1:PORT/enter?code=` + the code percent-encoded outside `A–Z a–z 0–9 - . _ ~`.
- `alive.check(port, timeout_ms) bool`: libc socket, non-blocking connect and poll (std's connect timeout panics), `GET /alive HTTP/1.1` with `Host: 127.0.0.1:PORT` and `Connection: close`; true only for status 200 within the time.

### Task 4: The controller

**Files:** create `src/controller.zig`.

**Produces:** `Controller.init(gpa) Controller`; `c.handle(now_ms: i64, ev: Event, out: *std.ArrayList(Effect), a) !void`; `c.port() ?u16`, `c.showingBuiltin() bool`.
- `Event`: `start`, `tick`, `checked: { gen, result: union { no_desk, bad_desk, dead: Desk, alive: Desk } }`, `entered: { gen, code: ?[]const u8 }`, `message: { msg: bridge.Message, source }`, `menu: enum { start, stop, autostart, reload }`, `loaded: { status: u16, url }` (main-frame response), `failed` (main frame couldn't load), `crashed` (web content gone), `ran: { cmd, ok, out }`, `exited_early: { code }`.
- `Effect`: `show: { screen: enum { setup, down, connecting }, note }`, `load: url`, `reload`, `check: gen`, `enter: { gen, home }`, `run: { cmd: enum { run, stop, autostart_on, autostart_off, autostart_query }, binary, home, path }`, `badge: u32`, `attention`, `menu: { start, stop, autostart_enabled, autostart: ?bool }`, `alert: { title, text }`.
- States `setup → down → connecting → in`. Checks every 5 s (every 1 s for 15 s after Start or Stop), one at a time; each re-reads desk.json. `no_desk`/`bad_desk` → setup. `dead` → down (from `in`: on the second miss in a row). `alive` from setup/down → connecting, show, enter. Entry code → load the enter URL, state `in`; no code → stay connecting with a note, the next check enters again. One entry at a time. `reenter` (desk source) → check, then enter without changing the screen. `start` (builtin source) and menu Start → run `run`; no binary → alert. Response 401/403 while in → enter again, at most once per 5 s. `failed`/`crashed` while in → check now. badge/attention only from the desk source.

- [ ] Tests: `no_desk_json_shows_setup`, `desk_json_appearing_is_noticed`, `alive_enters_and_loads_the_enter_url`, `no_code_stays_connecting_and_tries_again`, `two_missed_checks_while_in_show_down`, `one_miss_then_alive_stays_in`, `reenter_checks_then_enters_without_a_screen`, `reenter_during_an_entry_is_ignored`, `start_runs_harness_and_checks_fast`, `start_without_a_binary_says_so`, `stale_results_are_dropped`, `badge_and_attention_from_the_desk_page_only`, `a_new_port_in_desk_json_is_used_from_the_next_check`, `refused_entry_enters_again_at_most_every_5_s`, `menu_state_follows`.

## Rulings

(Each: what — why — cost if wrong. Added to as they are made.)

1. The data folder: `--home`, else HARNESS_HOME, else `$XDG_DATA_HOME/harness`, else `~/.local/share/harness` — harness's own order, so the app and the CLI agree when both see the same environment — cost if wrong: a HARNESS_HOME in the app's launch environment points it where harness itself would go.
2. desk.json is a JSON object `{"binary", "port", "home", "version"}`, plus an optional `"path"` (harness's PATH at its start, given to the commands the app runs, since an app opened from the Dock has launchd's short PATH); only `port` is required; unknown fields are ignored — cost if wrong: one rename here when platform/desk names them otherwise.
3. The folder desk.json was read from is the one the app writes requests in and passes as `--home`; desk.json's `home` is only shown — cost if wrong: a desk.json copied to another folder steers commands to the folder it sits in.
4. `state/open-request` holds `pid N`; a stale `state/desk-code` is deleted before each request — cost if wrong: none found (neither holds anything reusable).
5. The app waits up to 30 s for the code, every 100 ms; an empty file is "not written yet"; after 30 s the next liveness check starts over — cost if wrong: a harness slower than 30 s gets a second request.
6. Liveness is a 200 to `GET /alive` within 3 s; it's also checked while the desk is shown, and two misses in a row show "harness isn't running" — the page can't be relied on to notice harness gone — cost if wrong: one loopback request every 5 s while the desk is shown.
7. After Start or Stop, checks run every second for 15 s, then every 5 s — "enter as soon as it answers" — cost if wrong: a few more loopback requests.
8. Navigation: exactly `http://127.0.0.1:PORT` stays (and `about:blank`/`about:srcdoc`); `http`, `https` and `mailto` elsewhere from the main frame or a new window go to the system browser; subframes elsewhere and every other scheme are cancelled; a same-origin new-window request loads in the window — cost if wrong: a framed app's plain link to the web does nothing (its `target=_blank` and `_top` links work).
9. (Overturned at the final review: the handler is `harness`, the name platform/desk's page posts to.) The bridge's handler is `window.webkit.messageHandlers.desk`; the body is an object or JSON text; badge, attention and reenter count only from the main frame on the harness origin; `{"start": true}` only from the built-in page — cost if wrong: the desk page must use the name `desk`.
10. The microphone is granted only to the main frame on the harness origin; the camera is always denied — "for this origin only", and apps aren't the desk — cost if wrong: a framed app can't record.
11. Closing the window hides it; the app keeps running with its badge; the Dock icon brings it back; Quit quits — the badge and the urgent bounce are only useful while the app runs — cost if wrong: an owner who expects close to quit sees it stay in the Dock.
12. (Overturned at the final review: the bundle is `harness-desk.app`, which platform/desk's `harness open` looks for; running, LaunchServices names it "harness", which the Dock and menu bar show.) The bundle is `harness.app` (the Dock and Finder show the bundle's file name), its program `harness-desk`, its id `io.github.legatia.harness-desk` — cost if wrong: `harness open` must say `open -a harness` (or `open -b io.github.legatia.harness-desk`); renaming later loses the saved frame and the microphone permission.
13. One universal `.app` (arm64 and x86_64 by `lipo`), not two — cost if wrong: none found.
14. Test hooks (command file, log, external links logged instead of opened) are compiled in only with `-Dtest-hooks`; the smoke's app has its own bundle id; the release app has none of them — cost if wrong: the smoke runs a binary with extra logging.
15. `requestUserAttention:NSInformationalRequest`, one bounce — "once" — cost if wrong: none.
16. The badge shows the number as given (capped at 99999); 0 clears it — cost if wrong: none.
17. `harness run` is started with stdio on /dev/null in its own process group and reaped by a thread; if it exits within 10 s with a failure, an alert says so and to run it in Terminal to see why — its output can't be piped to an app that may quit first — cost if wrong: the reason is in harness's own log, not the alert.
18. `harness autostart` with no `on|off` prints `on` or `off` as its first word; the menu's check mark follows it, and after a toggle the asked state — cost if wrong: the item shows unchecked until toggled.
19. The user agent gains `harness-desk/VERSION`, so harness can tell the app's view from a browser — cost if wrong: none.
20. A 401 or 403 for the main frame while the desk is shown enters again, at most every 5 s — a session that ended without the page's reenter still recovers — cost if wrong: a page that is 403 for another reason is retried every 5 s.
21. JavaScript alert and confirm show as sheets; file inputs open the system file panel (the avatar upload needs it) — cost if wrong: none.
22. The fake harness is Python 3 (headsound's smoke uses python3 too), so the Windows and Linux apps can reuse it — cost if wrong: a Python dependency in tests only.
23. The smoke runs only in a GUI (Aqua) session and says SKIP otherwise; WebGL 2, autoplay and speech are required locally and reported on CI, where the runner may have no GPU or audio — cost if wrong: CI can't catch WebKit turning WebGL 2 off.
