# The gate as an MCP proxy for other agents: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `harness run` serves the tools of the owner's MCP servers to outside agents over Streamable HTTP, each call decided by the gate as `client:NAME`.

**Architecture:** A new module, `mcpserve.zig`, is an HTTP server shaped like `voiceagent.zig`: it knows tokens, JSON-RPC and limits, and hands listings and calls to a backend. The core is the backend: it holds a claim `/reload` respects, builds a run as the app act does (`runIn`, a tagging asker, `agent.stepCall`) with the who `client:NAME`, and returns the masked text. `who.zig` gains the kind `client`; `config.zig` gains `[proxy]` and the `[client NAME]` sections.

**Tech Stack:** Zig 0.17.1; `std.http.Server` over `sock.zig`; the stand-in MCP server of the tests (`harness-fake --mcp`).

**Spec:** `docs/superpowers/specs/2026-11-27-harness-mcp-proxy-design.md`

## Global Constraints

- Loopback only: `[proxy] listen` is 127.0.0.1 or ::1 with a port, or `off`; default `127.0.0.1:8766`.
- A token has 32 characters or more; only its SHA-256 is kept; it is masked and never logged or printed.
- The token is checked before the body is read; the body is at most 1 MiB.
- Nothing is offered to a client unless its section names the server; no `*`.
- Money: refused for a client without `money = on`, exactly: `a client's calls move no money ([client NAME] money = on)`; with it, asked every time.
- A call or listing holds `proxy_active` (taken under `settings_mutex` while not `restarting` and not `quitting`); `/reload` is Busy while it is above 0; close waits for it. It is not `bg_active`.
- Tests use the stand-in server and a temp home only; no real provider, no real harness data.
- Copy: plain statements. Every behaviour change is tested first (the test is seen failing).

## Review Focus

1. A request arriving between `/reload`'s check and the servers' restart: it must not read the freed tool list (it waits on `restarting`, at most 3 s, then is answered with an error).
2. The client hangs up while its approval waits: the item is withdrawn and the real server is never called, also when the owner presses "Allow once" a moment later.
3. A client named in config whose section is removed by `/reload` while its old connection is kept: its next request is refused (the proxy restarted; the old token no longer answers).
4. A tool of a server the client doesn't name, called by its full name: refused before the gate, nothing asked, nothing logged as a decision of the owner's.
5. Two clients, one with an "Allow 24 h" grant: the other's same call still asks.

### Task 3: the server

**Files:** Create `harness/src/mcpserve.zig`; `harness/src/main.zig` or the test root (so its tests run)

**Produces:**
```zig
pub const min_token = 32;
pub const ClientToken = struct { name: []const u8, token: []const u8 };
pub const Listed = union(enum) { tools: []const u8, busy }; // tools: the JSON array's text
pub const Called = union(enum) { result: struct { text: []const u8, is_error: bool }, unknown, busy };
pub const Backend = struct {
    ctx: *anyopaque,
    list: *const fn (ctx: *anyopaque, a: std.mem.Allocator, client: []const u8, gone: *std.atomic.Value(bool)) Listed,
    call: *const fn (ctx: *anyopaque, a: std.mem.Allocator, client: []const u8, name: []const u8, args_json: []const u8, gone: *std.atomic.Value(bool)) Called,
};
pub const Options = struct { listen: []const u8, clients: []const ClientToken, backend: Backend, log: ?*log_mod.Log = null, max_body: usize = 1 << 20, head_ms: u32 = 10_000, idle_ms: u32 = 60_000, max_connections: u32 = 32, calls_per_client: u32 = 4 };
pub const Server = struct { pub fn start(gpa, io, o: Options) !*Server; pub fn stop(s: *Server) void; pub fn address(s: *const Server) []const u8; port: u16, ... };
pub fn request(io, a, host, port, r: Request) !Reply; // Request{ method = "POST", path = "/mcp", auth: ?[]const u8, body, origin: ?[]const u8 = null, version: ?[]const u8 = null }
```
`start` errors: `BadAddress`, `ShortToken`, `SameToken`, `NoClients`, `TooManyClients`, the listener's.

`gone` is set while a backend call goes when the connection becomes readable (the client hung up) or the server stops; a watcher thread polls `sock.readableNow` every 50 ms for the call's time.
