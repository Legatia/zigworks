# harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** harness v0.1.0: a personal agent driven from Telegram or the terminal, models through omnigate, every tool call through one gate and one hash-chained log, ranked memory, morning briefs.

**Architecture:** One Zig binary, one data folder per instance. Modules: config, rules+gate, log, memory, model client, tools, agent loop, feeds+brief, telegram, core (runs, queue, commands, scheduler), CLI. A second binary `harness-fake` stands in for omnigate, Telegram, feeds and search in tests.

**Tech Stack:** Zig 0.17.1 std only (+ Security/CoreFoundation on macOS for the key store). Copied modules from llmcheck (`sock.zig`, `http.zig`, `jv.zig`) and keygate (`store.zig`, `scrub.zig`).

**Spec:** `docs/superpowers/specs/2026-11-19-harness-design.md`

## Global Constraints

- Zig 0.17.1 (`~/.local/zig/zig-aarch64-macos-0.17.1`), std only; project in `harness/` with its own copies of shared files, no cross-project imports.
- Linux, macOS, Windows; CI matrix gets `harness` (incl. windows-latest).
- omnigate only: `POST {url}/v1/messages`, header `x-api-key`, `anthropic-version: 2023-06-01`; 402 = budget spent (no retry); 429 = wait `retry-after` capped at 60 s, once.
- Secrets via `store.zig` with service name `harness`; never in tool environments; output containing a stored secret is masked before model and log.
- Defaults: steps_per_turn 20, turn_seconds 600, tool_output_bytes 16384, conversation_bytes 200000, concurrent_runs 2, approval_seconds 600, top_size 20, max_tokens 4096.
- Memory: strength `ln(Σ (age_days+1)^-0.5)`; middle/bottom line −1.0; recall thresholds 30% (middle) / 70% (bottom); max 8 recalled; mention at ≥50%; dedup at ≥80%; quiet 30 min → memory writer, ≤5 items.
- Telegram: long polling timeout 50 s; split at 4,096 chars; pair code valid 10 min.
- Seen feed items kept 60 days. Log stores args/output up to 2 KB; private mode stores metadata + SHA-256 only.
- Copy: plain labels, no slogans (user's CLAUDE.md).

## Review Focus

1. Restart after a crash: Telegram updates must not be handled twice (persist `offset` in `state/telegram`), and a half-written last log line must not break the chain forever (on start: truncate a final line without `\n`, then log `recovered`). Tests in Tasks 3 and 9.
2. A shell command that ignores stop or spawns children: `/stop` and the time limit must end it (process group kill on POSIX, job/`TerminateProcess` on Windows). Test in Task 6.
3. Hostile or huge feeds and fetches: bodies capped (feeds 4 MiB, fetch 1 MiB), malformed XML gives zero items and a note, not a crash. Tests in Tasks 6 and 8.
4. Owner types text while an approval is waiting: the text is queued; only the button (or `/stop`) answers the approval. Test in Task 10.
5. Brief time missed while the process was down: on start, if today's `at` has passed and the brief has not run today, run it once. Test in Task 10.
