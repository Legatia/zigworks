# harness: importing a Hermes setup, and `harness skill` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `harness import hermes [--from DIR] [--profile NAME] [--dry-run] [--yes] [--bundled]` reads a Hermes v0.23.4 home and brings over memory, `SOUL.md`, user skills, cron jobs, MCP servers, deny patterns and the model, writing only what maps (narrowing, never widening), copying every harness file it changes first and leaving a report; `harness skill add|list|show|update|rm` installs agentskills.io skills from a folder, a GitHub repo (codeload tar.gz, pinned to the archive's commit) or a link to a `SKILL.md`, keeping each one's source and hash.

**Architecture:** New files hold the work: `yaml.zig` (the block subset Hermes writes), `zones.zig` (an IANA zone's offset on a day, from TZif files and their POSIX footer), `hermes.zig` (finding and reading a Hermes home into a `Setup`), `hermes_import.zig` (the plan, its text, writing it, the report, the command), `targz.zig` (gzip + tar reading with limits and the pax commit; a stored-deflate writer for tests and harness-fake), `skillsrc.zig` (shared by both commands: `skills/.sources`, a skill's hash, frontmatter facts, installing a folder), `skill_cmd.zig` (the `harness skill` commands), `taskfiles.zig` (`do_file` and the guarded `tasks/` folder). Small local edits: `main.zig` (dispatch, usage, init's notice), `mcp.zig` (`env =`), `triggers.zig`/`config.zig` (`do_file`), `core.zig` (two hook lines in settings loading, one in MCP start, `Paths.tasks_dir`), `skills.zig` (a closing fence with trailing spaces), `memory.zig` (one read-only `repeatOf`), `fake.zig` (a codeload route), `fake_mcp.zig` (echo of a plain env value), `smoke.sh` (one block of its own).

**Tech Stack:** Zig 0.17.1, std only (`std.json`, `std.tar`, `std.compress.flate`, `std.tz`, `std.crypto.hash`); macOS, Linux, Windows.

**Spec:** `docs/superpowers/specs/2026-11-24-harness-hermes-import-design.md` (binding; its "Calls I made" are decided, its tables are the expected outcomes). Hermes's own source at v0.23.4 for shapes: `cron/jobs.py`, `tools/memory_tool_store.py`, `hermes_cli/default_soul.py`, `hermes_cli/config_defaults.py`, `hermes_cli/config_providers.py`, `tools/skills_hub*.py`, `tools/skills_sync.py`, `tools/mcp_tool_registration.py`, `tools/mcp_tool_common.py`, `tools/cronjob_tools.py`, `hermes_constants.py`, `agent/skill_utils.py`, `tools/skills_tool_setup.py`.

## Global Constraints

- Another builder (`platform/inject`) works at the same time on gate.zig, agent.zig's call path, core.zig's memory writer, conversations' state, telegram.zig, smoke.sh, README, the gaps list, the ledger and HANDOFF's top: code in new files; edits to main.zig, config.zig, core.zig, mcp.zig, skills.zig small and local; smoke checks in one block of their own; README section "Coming from Hermes" of its own; docs appended, not rewritten.
- No secret is copied, printed or logged: fixtures use obvious fakes (`sk-fixture-…`); every import and skill test checks no fixture secret value appears in any harness file, the output or the log. The real `~/.hermes` and the owner's harness folder are never read.
- An import narrows, never widens: deny patterns and excluded tools become deny rules; `command_allowlist` becomes a suggestions file of commented lines; `allowed-tools` is shown and ignored.
- Copy (CLAUDE.md): plain labels, sentence case, short lines, no slogans.
- Files written whole (`util.writeReplace`); settings files 0600; `tasks/` and `skills/` created 0700 like `workflows/`; harness's own memory store API for items.
- Windows: Hermes's home is `%LOCALAPPDATA%\hermes`; joined paths `std.fs.path.sep_str` in tests; dirs that are listed opened `.iterate = true`; no executable bit; the tar reader refuses names Windows can't hold; text reads the same with `\r\n`; POSIX-only tests skip on Windows.
- Baseline: harness 1198 pass, 22 skipped (unit binary run directly); smoke 109 (142 with the stand-ins). Tests from `harness/`: `zig build test --summary all --cache-dir $SCRATCH/zc > FILE 2>&1`, `-Dtest-filter=NAME` while iterating, Debug and ReleaseSafe, with and without `HOMEMCP_BIN`, `CARCLOUD_BIN`, `CALMCP_BIN`, `MAILMCP_BIN`; cross builds (`zig build` and `unit-build`, x86_64-windows, x86_64-linux-musl, aarch64-linux-musl) into scratch.

## Review Focus

The inputs most likely to bite someone switching, each pinned by a test in the task that owns it:

1. **A secret in an unexpected place**: a literal key in an MCP server's `env`, a `headers` value, a provider's `api_key`, a memory entry or a cron prompt holding a `.env` value. Nothing of it reaches a harness file, the plan, the report or the log (masked as `[secret:NAME]` in text the owner should see). (`no_secret_value_reaches_any_file_output_or_log`, Task 6.)
2. **A prompt `tasks.ini` would cut**: a prompt with ` ;`, ` #`, a newline, or leading spaces. It goes whole into `tasks/NAME.md`, and the task run sends it whole. (`a_prompt_tasks_ini_would_cut_goes_to_its_own_file`, Task 5; `a_task_with_do_file_runs_its_file`, Task 1.)
3. **An `at` time across midnight**: a job at 00:30 in UTC+2 for a harness at +00:00 becomes 22:30 the day before, and its days move with it. (`a_converted_time_moves_its_days`, Task 5.)
4. **Running the import twice, or while `harness run` holds the folder**: nothing is added twice; a real import refuses while harness runs, `--dry-run` works. (`running_it_again_adds_nothing_twice`, `the_import_refuses_while_harness_runs_but_dry_run_works`, Task 6.)
5. **A hostile archive**: a link, `..`, an absolute path, a name Windows can't hold, too many files or bytes. Refused before anything is written. (`hostile_entries_are_refused`, `limits_stop_an_archive`, Task 7.)

## Rulings

(Each: what — why — cost if wrong. Added to as they are made.)

1. tasks/ is checked (go-w, files 0600-like) only when a task names a do_file — a folder nobody uses can't stop harness from starting — cost if wrong: an unused writable tasks/ goes unnoticed (it runs nothing).
2. an env = value equal to a stored secret is caught at server start (a "not started" note, as a missing secret is), not by parseConfig — the parser is pure and knows no secrets — cost if wrong: the reason shows in /status and start notes, not as a "line N has an error".
3. mcp.ini's env = refuses names with the spec's five words only (TOKEN, KEY, SECRET, PASSWORD, AUTH, any case); the importer's own secret test is wider (Task 5) — cost if wrong: a plain AUTHOR=x must be given as a secret.
4. a reload with a missing do_file says the reason in reload's text (as every settings problem does) — the plan's test said error.BadSettings, reload never returns it — cost if wrong: none.
5. yaml.zig's tests and reader were written in one sitting; their teeth were shown by a stub parser (all 7 failed), then the reader made them pass (one fix, folded blank lines) — cost if wrong: none found.
6. a zone is read from TZif files (TZDIR, /usr/share/zoneinfo, /var/db/timezone/zoneinfo, /usr/share/lib/zoneinfo, /etc/zoneinfo) and their POSIX footer past the last change; "" is this computer's (/etc/localtime); UTC/GMT need no file; Windows has no zone files, so the answer is null there — the spec asks for the zone's offset on the import day and std has TZif but no zone database — cost if wrong: on Windows a job in another zone keeps its written time and the plan says to check it.
7. an unedited bundled skill is found by Hermes's own hash (MD5 over the paths' parts in Python's order and the bytes, with or without caches); a manifest line without a hash (Hermes's v1) counts as bundled and unedited ("known": false) — Hermes itself can't prove such a skill edited — cost if wrong: an edited v1-manifest skill needs --bundled.
8. a skill's folder is copied whole with no nested skills looked for; links in it are listed (never followed or copied); __pycache__, .git, node_modules and venvs in it are left out — Hermes's own scan finds nested skills, but they are rare and a folder copied whole keeps them as files — cost if wrong: a nested skill comes over as files of its parent.
9. values from .env and literal keys in config.yaml are masked only when 8 or more characters and not under a name Hermes calls plain (_URL, _HOST, _USER, _ID, _DOMAIN, _SCHEME; also _USERS, _MODEL, _DIR, _PATH) — shorter values would mask ordinary words — cost if wrong: a 7-character key shows in a memory entry's text. **Partly overturned by the final review:** in an MCP server's command, args, url and env, an exact .env match has no floor (Ruling 44).
10. the import's secret test for an MCP env value or header (beyond the spec's words): a ${VAR} anywhere, a name with TOKEN, KEY, SECRET, PASSWORD, PASSWD, PASS, PWD, AUTH, CREDENTIAL, PRIVATE, COOKIE, SESSION, BEARER or JWT, a known key prefix (sk-, ghp_, github_pat_, xoxb-, glpat-, AKIA, AIza, eyJ, …), or 24+ letters-and-digits with no spaces — cost if wrong: a long plain id is asked for as a secret. **Partly overturned by the final review:** the test now covers the command, every argument and the url too, and also a password in an address (`scheme://user:pass@`), `${env:VAR}` and `${MY-VAR}`, and any .env value inside a value (Rulings 43–45).
11. Tasks 5 and 6 land in one commit (15bb7da): they share hermes_import.zig and Task 6's tests were written while Task 5's suite ran; each task's tests were seen failing on stubs first (Task 5: 19/19, Task 6: 12/12) — cost if wrong: a reviewer reads both in one diff.
12. the plan shows memory entries cut at 160 bytes on one line ("…"); they come over whole — the owner sees each without a wall of text; the full text is in memory (harness memory list) — cost if wrong: the owner reads a long entry's end only after the import.
13. Hermes's unedited bundled skills are one Not-imported line listing their names, not a line each — there are dozens, and a line each would bury the rest — cost if wrong: none found (every name is still there).
14. "already there" items (memory, SOUL, skills by hash, tasks by name and instructions, commented blocks by text, servers by name and command/url, rules by line, model and providers by value) go under Not imported with that reason — the spec's three groups have no fourth — cost if wrong: none.
15. command_allowlist entries are told apart by Hermes's own 122 pattern names (tools/approval_detection.py DANGEROUS_PATTERNS, kept in hermes.zig) and by a backslash (an old regex key); anything else is a command or a command glob — Hermes's v0.23.4 code stores "always" approvals as those names and manual entries as command text — cost if wrong: a new Hermes pattern name comes over as a commented `allow shell` suggestion (still never active).
16. a job delivered to a list counts as main when any item is origin, telegram, telegram:…, or all; a job whose deliver is absent or null is Hermes's "local" — cron's own code normalizes it so — cost if wrong: a job Hermes delivered by default comes over commented out.
17. a job's attached skills that aren't imported (Hermes's own, or refused) are still named in its "Use the skills" line, and the plan says they aren't imported — the instructions stay the job's — cost if wrong: the agent looks for a skill it hasn't; --bundled brings Hermes's own.
18. mcp.ini secret names: a ${VAR} → var lower-cased; a value found in .env → that variable lower-cased; a literal → the env name lower-cased; a clash between different values → SERVER-NAME; a literal bearer token → SERVER-token; a provider's key → the provider's name; a model preset's key → the preset's name (harness's own) — cost if wrong: the owner stores one key under two names.
19. an excluded MCP tool becomes `deny mcp SERVER/GLOB *` (the space and * cover any input), not the spec's `SERVER/TOOL*`, which would also deny every tool whose name starts the same — narrowing either way — cost if wrong: none found.
20. "harness has a provider set" = [model] provider other than omnigate, or omnigate with a url; only then is [model] left alone and the difference listed. A model with a `:` is written PROVIDER:MODEL; memory_model and worker_model are left, with a Needs-you line — cost if wrong: a fresh harness whose owner meant omnigate gets Hermes's provider (it prints in the plan first).
