# harness: people (section 3 of the butler's duties) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** harness knows the people the owner deals with. `state/people/` holds a small file per person (name, what the owner calls them, relation, birthday and other dates, preferences, how to reach them, when the owner last mentioned being in touch, a keep-in-touch interval), written whole. It is filled by the memory writer from the owner's own conversations, from calendar attendees when a calendar tool answers in one of them, and by `harness people import FILE.vcf`. A `people` tool (find, show, note) is offered only in runs the owner started in their own conversations. A week before a birthday or anniversary the owner gets one line with a gift idea from the person's preferences (searched, nothing bought); on the day, a reminder; with `keep in touch = 3 months`, a line when that long has passed. These are non-urgent posts: quiet hours hold them, and at most one goes a day.

**Architecture:** a new `people.zig` holds everything that is not wiring: the file format (`key = value` lines), `Book` (load, find, resolve, note, save through `util.writeReplace`), the vCard 3/4 reader, the memory writer's person lines, calendar attendees from a tool's JSON, what is due on a day (`Told` in `state/people-told`), the lines' words, the tool's definition and its call, and `meetingNote` for the diary. `gate.zig` gets the kind `people` (default allow; never a member's or a room's). `agent.zig` gets `Run.people` (null: no tool), the tool's offer, argument and call, and the calendar hook after an MCP call. `core.zig` gets one field (`people`), sets `run.people` in the owner's chat turns in their own conversations, extends the memory writer's prompt and reads its person lines, `/people` and `/person`, the daily pass on the tick (a gift-idea run with `search` only, as `schedule:people`), and `peopleForMeeting`. `main.zig`: `harness people list|show|import`. `fake_mcp.zig`: `--mcp --cal`, a calendar stand-in.

**Tech Stack:** Zig 0.17.1, std only; macOS, Linux, Windows.

**Spec:** `docs/superpowers/specs/2026-11-23-harness-butler-duties-design.md` §3, Tests, Calls; the butler spec's UX rules and red lines; the ledger's memory, long memory, conversations (own, shared, private), household (members, speech `room:NAME`), the tick, quiet hours.

## Review Focus: who may see people's data

What a reviewer checks first, each with the test that holds it:

1. **Only the owner's own runs get the tool.** `Run.allows(.people)` needs `Run.people` (set only by the owner's chat turn in a conversation whose audience is `own`), `who.by == "owner"`, and not a helper. Members, speech, schedules, triggers, workflows, helpers and shared conversations never see it in the request. (`people_tool_only_in_the_owners_own_conversations`, `members_and_speech_never_see_people`, gate `people_is_never_for_members_or_rooms`.)
2. **Only the owner's own words fill it.** The memory writer's person lines are applied only for a context of the owner's (not `member:`), in an `own` conversation, not private (checked again after the model call); calendar attendees only in a run with `Run.people` that is not private. (`the_writer_recognises_people_in_the_owners_own_conversations`, `no_people_from_shared_private_or_members_turns`, `calendar_attendees_become_people`.)
3. **Private conversations add nothing.** `note` answers "not saved: this conversation is private"; the writer skips them; attendees are not added. Reading (`find`, `show`) still works there, and its lines are private lines. (`a_private_conversation_adds_no_one`.)
4. **Lines go to main only**, as `schedule:people`, held in quiet hours. The gift idea's search query carries one interest, never a name, relation, allergy or date; the run's prompt has the preferences, not the name. (`a_birthday_week_line_has_a_gift_idea_from_a_search`.)
5. **`/people` and `/person`** are owner commands: a member's are refused as today, and the owner's in a group are dropped as today (only `/conversation add` is read there). (`members_and_speech_never_see_people`.)
6. **Files**: `state/people/` 0700, files 0600 (as `util.writeReplace` writes), written whole; a file's name is its id; names that would leave the folder are refused.

## Rulings

(Each: what – why – cost if wrong.)

1. **One file per person, `key = value`, named from the name.** What: `state/people/ID.txt`, ID the name in lower-case Latin letters without marks (`Łukasz Żółć` → `lukasz-zolc`, `-2` on a clash); the file's name is the id; lines harness doesn't read are kept at the end; `\r\n` reads as `\n`. Why: the owner can read and edit them; names safe on every file system. Cost if wrong: a person renamed keeps the old file name.
2. **Who gets the tool.** What: `Run.people` is set only by the owner's chat turn (text, voice note, `/ask NAME`) in a conversation whose audience is `own` (or main and the terminal before they have an entry); `allows(.people)` also needs `who.by == "owner"` and not a helper; a definition's `tools` decides it as any tool's. Why: the spec's "the owner's own conversations only"; helpers answer their run and never write. Cost if wrong: a schedule, trigger or workflow can't use the tool (the day's pass covers birthdays).
3. **Private conversations read but add nothing.** What: `find` and `show` work there (their lines are private lines); `note` answers "not saved: this conversation is private"; the writer skips them (as before) and checks again after its model call; calendar attendees are not added. Why: "private conversations add nothing", while looking someone up stays possible. Cost if wrong: none found.
4. **The memory writer notes people in the same call.** What: in the owner's own conversations its prompt asks for `person: NAME | FIELD | VALUE` lines besides its `- ` lines, and says people's facts go only there; it is shown the people known (names, what the owner calls them, relations; no other fact). A name several people share is skipped; a new name makes someone new. One line per person given something new ("Noted about Ola: …. (/person Ola)"); being in touch alone is noted silently. Not for members' contexts, shared or private conversations. Why: one model call, no new cost; no surprises. Cost if wrong: a fact about a person no longer also becomes a memory item in the owner's own conversations (it is in their file, reached through the tool).
5. **`in touch` means the owner said they were in touch.** What: set by the writer's `in touch` line or the tool's note, dated the day the owner wrote it (the context's last owner message), never by a mere mention; keeping in touch counts from it, else from when the owner asked to keep in touch (`added`, set again when `keep in touch` is set with no in-touch day known); said again after each further interval. Why: "I should call Ola" is no contact. Cost if wrong: an owner who never says "I called her" gets the line every interval.
6. **One post a day.** What: every birthday and anniversary of the day share that day's post (never moved to another day); else the single nearest week line; else the longest wait to keep in touch; the rest on the following days; a week line not said by the day before is dropped (the day's own reminder follows); a day harness didn't run is not made up later. Why: "at most one such line a day, the rest in the next day's", without moving a birthday. Cost if wrong: two birthdays on one day make a two-line post; a birthday while harness was down gets no reminder.
7. **09:00 the owner's time, no setting.** What: the first tick from 09:00 where `harness run` or `harness chat` runs; the post goes to main as `schedule:people`, so quiet hours (and later a busy calendar) hold it for the digest; told lines are kept in `state/people-told` before the post (a crash never says one twice); a post that does not get through is a delivery item, sent again. Why: no change to config.ini while two other builders change it. Cost if wrong: an owner who wants it at 07:00 can't move it yet.
8. **The gift idea: one interest searched, the name never sent.** What: only a preference that says what the person likes (`likes`, `loves`, `enjoys`, `is into`, `fan of`, `collects`, `reads`, `plays`, `listens to`, `watches`, `follows` …) is searched, as "gift ideas for someone who likes Polish poetry", by harness itself as a call of `schedule:people` the gate decides and the log keeps; then one memory-model call gets the occasion, all the preferences (so an allergy is kept in mind) and the results, never the name, relation, age or date; no such preference: no search and no idea. Nothing is bought. Why: an allergy or a diet is health data a search engine should not get. Cost if wrong: an interest written without those words ("Polish poetry") gets no idea.
9. **Calendar attendees.** What: from the answers of calmcp's reads `cal_event` and `cal_agenda` (any server name), every `attendees` list in their JSON (objects with name/cn/displayName and email/mail, or `Name <email>` strings); `"self": true` left out, lists of more than 10 left out, someone with an email alone left out; matched by email or whole name; the new ones said in one line. Why: calmcp isn't built yet; this needs no change on its side beyond attendees in its answers. Cost if wrong: if calmcp's answers have another shape, nobody is added (nothing else happens).
10. **vCard merge.** What: a card is the person with one of its emails, else its whole name, else (someone known by a first name alone, exactly one) its first name, who then takes the card's full name and keeps the old as `called`; what is known stays, the card adds the missing; `NOTE`, `ADR`, `ORG`, `PHOTO` are not read; a year before 1900 is no year (Apple writes 1604). Why: the writer's "Ola" and the address book's "Ola Kowalska" are one person. Cost if wrong: a card whose first name is the single name of a different person merges into them.
11. **`harness people` opens the data folder as `harness memory` does.** What: with `harness run` stopped. Why: one writer for `state/people/`. Cost if wrong: an import needs `harness run` stopped for a moment.
12. **The tool's note is said to the owner**, like `remember`'s ("Noted for Ola: likes Polish poetry. (/person Ola)"). Why: no surprises. Cost if wrong: the model's reply may say it again.
13. **Limits.** 5,000 people, 16 KB a file, 16 values of a kind, 200 bytes a value; an import that reaches 5,000 says so. Why: everything is in memory and in files read whole. Cost if wrong: a larger address book is cut.
14. **Day and keep-in-touch lines carry how to reach them** (the first phone, else the first email). Why: a butler's reminder you can act on. Cost if wrong: none found; they go to main only.
