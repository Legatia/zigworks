# harness: people (section 3 of the butler's duties) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** harness knows the people the owner deals with. `state/people/` holds a small file per person (name, what the owner calls them, relation, birthday and other dates, preferences, how to reach them, when the owner last mentioned being in touch, a keep-in-touch interval), written whole. It is filled by the memory writer from the owner's own conversations, from calendar attendees when a calendar tool answers in one of them, and by `harness people import FILE.vcf`. A `people` tool (find, show, note) is offered only in runs the owner started in their own conversations. A week before a birthday or anniversary the owner gets one line with a gift idea from the person's preferences (searched, nothing bought); on the day, a reminder; with `keep in touch = 3 months`, a line when that long has passed. These are non-urgent posts: quiet hours hold them, and at most one goes a day.

**Architecture:** a new `people.zig` holds everything that is not wiring: the file format (`key = value` lines), `Book` (load, find, resolve, note, save through `util.writeReplace`), the vCard 3/4 reader, the memory writer's person lines, calendar attendees from a tool's JSON, what is due on a day (`Told` in `state/people-told`), the lines' words, the tool's definition and its call, and `meetingNote` for the diary. `gate.zig` gets the kind `people` (default allow; never a member's or a room's). `agent.zig` gets `Run.people` (null: no tool), the tool's offer, argument and call, and the calendar hook after an MCP call. `core.zig` gets one field (`people`), sets `run.people` in the owner's chat turns in their own conversations, extends the memory writer's prompt and reads its person lines, `/people` and `/person`, the daily pass on the tick (a gift-idea run with `search` only, as `schedule:people`), and `peopleForMeeting`. `main.zig`: `harness people list|show|import`. `fake_mcp.zig`: `--mcp --cal`, a calendar stand-in.

**Tech Stack:** Zig 0.17.1, std only; macOS, Linux, Windows.

**Spec:** `docs/superpowers/specs/2026-11-23-harness-butler-duties-design.md` §3, Tests, Calls; the butler spec's UX rules and red lines; the ledger's memory, long memory, conversations (own, shared, private), household (members, speech `room:NAME`), the tick, quiet hours.

## Review Focus: who may see people's data

What a reviewer checks first, each with the test that holds it:

1. **Only the owner's own runs get the tool.** `Run.allows(.people)` needs `Run.people` (set only by the owner's chat turn in a conversation whose audience is `own`), `who.by == "owner"`, and not a helper. Members, speech, schedules, triggers, workflows, helpers and shared conversations never see it in the request. (`people_tool_only_in_the_owners_own_conversations`, `members_and_speech_never_see_people`, gate `people_is_never_for_members_or_rooms`.)
2. **Only the owner's own words fill it.** The memory writer's person lines are applied only for a context of the owner's (not `member:`), in an `own` conversation, not private (checked again after the model call); calendar attendees only in a run with `Run.people` that is not private. (`the_writer_recognises_people_in_the_owners_own_conversations`, `no_people_from_shared_private_or_members_turns`, `calendar_attendees_become_people`.)
3. **Private conversations add nothing.** `note` answers "not saved: this conversation is private"; the writer skips them; attendees are not added. Reading (`find`, `show`) still works there, and its lines are private lines. (`a_private_conversation_adds_no_one`.)
4. **Lines go to main only**, as `schedule:people`, held in quiet hours. The gift idea's search query carries one interest, never a name, relation, allergy or date; the run's prompt has the preferences, not the name. (`a_birthday_week_line_has_a_gift_idea_from_a_search`.)
5. **`/people` and `/person`** are owner commands: a member's are refused as today, and the owner's in a group are dropped as today (only `/conversation add` is read there). (`members_and_speech_never_see_people`.)
6. **Files**: `state/people/` 0700, files 0600 (as `util.writeReplace` writes), written whole; a file's name is its id; names that would leave the folder are refused.
