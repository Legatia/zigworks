# harness phase 0: the shared gate foundation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every run carries a who (`by`, `agent`, `parent`) into the gate and the log; rules get who sections and `shell@ENV`; grants get `who` and `@ENV`; the gate knows the platform's new kinds, their defaults and setup calls. 0.3's tests pass unchanged.

**Architecture:** A new `who.zig` holds `Who` and the who patterns. `rules.zig` reads sections and environments into each `Rule`; `gate.zig` decides in the overview's seven steps with `Ctx.who` and `Ctx.env`, keeps grants with environment and who (a versioned `state/grants`), and adds the kinds. `log.zig` writes a run's tag (`rid`, `run`, `by`, `agent`, `parent`); `agent.Run` carries its who and id and writes its lines through it; `core.zig` starts chat turns as `owner`, tasks and briefs as `schedule:NAME`, and takes "nobody can answer" from that.

**Tech Stack:** Zig 0.17.1, std only.

**Spec:** `docs/superpowers/specs/2026-11-22-harness-platform-overview.md` ("Rules every spec keeps", "Shared formats", "Phase 0"), and the who, rules, grants and kinds parts of the eight gap specs beside it.

## Global Constraints

- Zig 0.17.1, std only; macOS, Linux, Windows. At the end these compile: `zig build -Dtarget=x86_64-windows`, `-Dtarget=x86_64-linux-musl`, `-Dtarget=aarch64-linux-musl`, and `zig build unit-build` for each; `zig build test -Doptimize=ReleaseSafe` passes.
- "It changes no behaviour by itself: 0.3's tests pass unchanged." No existing test is edited. Baseline: 380 pass, 2 skipped, `smoke: all ok`.
- Who is one token, `KIND` or `KIND:NAME`, never with a space: `owner`, `schedule:NAME`, `trigger:NAME`, `workflow:NAME/STEP`, `app:NAME`; `agent:NAME` names a definition in patterns, never a `by`. A pattern is a who value with `*` as in rules; a bare kind covers every name of that kind; `workflow:NAME` covers all its steps; `agent:` patterns match definitions, the others `by`.
- Chat turn: `owner`, `main`. Task or brief (also run by hand): `schedule:NAME`, `main`. Helper: its parent's `by`, `helper`, `parent`.
- Rules: `ACTION TOOL[@ENV] PATTERN`; `@ENV` only for `shell`; `shell` matches every environment, `shell@box` only box; `[PATTERN]` starts lines for calls whose who it matches; lines before the first header, or after `[all]`, apply to every call. `host` is the only environment until gap 2.
- Gate order: 1 hard limits; 2 roles (empty until gap 3); 3 a matching `deny` in the shared part or a section matching D, D1…Dk or `by`; 4 listed sources, money and setup calls (asked every time); 5 a grant for this TOOL[@ENV] and key whose `who` is empty, `agent:D`, or matches `by`; 6 the first matching `allow` or `ask` in a section matching D, then one matching `by`, then the shared part, an `ask` in a section matching D1…Dk or `by` turning an allow from another section into ask; 7 the kind's default, `ask` is deny where nobody can answer.
- Grants: `TOOL[@ENV]`, expiry (Unix seconds), key (as today), `who` (empty: any run, as 0.3's lines); tab-separated; a shell grant always names its environment, a 0.3 line without one is `shell@host`. Allow 24 h writes `agent:D`.
- Kinds and defaults: `send` (own: allow; shared: asked every time, no Allow 24 h, an `allow` rule lifts it), `ask_owner` allow, `mail` ask, `trigger` (`add` setup, `rm` ask, others allow), `workflow` (`save` setup, `start`/`stop` ask, others allow), `agent_save`, `app_save`, `env_save` setup, `app_read`, `app_draft`, `snapshot` allow.
- Setup calls: asked every time like money: Allow once and Deny only; no grant or `allow` rule lifts it; a `deny` rule stops it.
- Log: a run's first line `rid` (that line's `seq`), `run`, `by`, `agent`, `parent` (a delegated run); later lines `rid`; `gate` and `tool` lines also `agent` (`conversation` comes with gap 4).
- Copy: plain labels, no slogans. Every new Core field is set in `Core.open`.

## Rulings

1. **`state/grants` gets a first line and escaped keys.** What: a file phase 0 writes starts with `# harness grants 2: ...`; its lines have exactly four fields, and keys write `\`, tab, CR and LF as `\\`, `\t`, `\r`, `\n`. A file whose first line does not start with `#` is 0.3's and is read exactly as before (key = everything after the second tab, who empty). Why: 0.3 lines have no who field and their keys can hold tabs, so a fourth field can't be told from part of a key; and in 0.3 a 24 h grant for a command with a line break (a heredoc) wrote a second grant line of the model's making, which could grant `rm -rf /` until any expiry it chose. Cost if wrong: a reader that expects only grant lines must skip one comment line; going back to 0.3 drops the grants (it never widens them).
2. **A 24 h grant covers the definition that asked, so one from the chat no longer covers helpers.** What: Allow 24 h writes `agent:main` in the chat's runs and tasks, `agent:helper` in a helper's; a 0.3 grant (empty who) still covers every run. Why: the overview fixes `agent:D` (per-definition grants are its point); no 0.3 test relies on a chat grant covering a helper. Cost if wrong: an owner who allowed a command for 24 h in the chat is asked again when a helper runs it.
3. **Task and brief names are not checked against the name rule.** What: `by` is `schedule:` and the name as written; a name with a space, `:`, `/` or `*` (0.3 allowed any name without `[`, `]` or a line break) gives a `by` no section can name exactly (`[schedule]` or a `*` pattern reaches it). Why: refusing such names would refuse 0.3 files. Cost if wrong: such a `by` breaks "never with a space" in the log; phase A's one parser for tasks, briefs and triggers should enforce the rule and tell the owner.
4. **An ask in a delegator's or origin's section also narrows a default allow.** What: `[agent:main] ask read_file *` makes main's helpers ask for `read_file`, whose default is allow. Why: the overview says such an ask "turns an allow from another section into ask", and a default is in no section, but the agents spec's test ("a delegating definition's section denies and asks for its delegated runs") needs it. Cost if wrong: such an ask is stricter than meant. Two headers with the same pattern are one section (its first matching line decides).

## Review Focus

1. A 0.3 `state/grants` whose keys hold tabs, and a new 24 h grant whose key holds a line break: read as before, and the line break stays inside its grant (Task 4 test).
2. A mistyped header (`[agnet:coder]`, `[schedule btc]`, a comment after `]`) or `fetch@box`: harness refuses `rules` naming the line and why, never ignores the section (Task 2 test).
3. A task or brief named with a space (`[weekly review]`): it still runs unattended, logs `by` as is, and `[schedule]` still reaches it (Task 1 test).
4. The model calling a kind that has no tool yet (`send`, `agent_save`, `trigger` …): refused as not available, never reaching the gate or `tools.run` (Task 5 test).
5. Two helpers writing at once: each line carries its own run's `rid`, never a sibling's or the parent's (Task 7 test).
