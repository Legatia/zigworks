# zigworks

Open-source tools written in Zig, mostly infrastructure for coding agents. Each folder is a standalone project with its own README, tests and MIT license, and no dependencies beyond the Zig standard library (and libc where noted).

| Project | What it does |
|---|---|
| [trigrep](trigrep/) | Indexed code search. ripgrep-compatible output; on the Linux kernel, with its file watcher running (`trigrep watch`, or built into the MCP server), searches take 12–160 ms against ripgrep's 1.4 s, and still see every edit. CLI and MCP server; macOS, Linux and Windows. |
| [headterm](headterm/) | Headless terminal for agents. Runs a program in a pseudo-terminal and gives the screen as text, row diffs, key input and waits, and which text is highlighted (inverse, bold, colours), so agents can drive vim, less, REPLs, menus and installers. CLI and MCP server; macOS, Linux and Windows 10 or later (ConPTY). |
| [headsight](headsight/) | Sight for agents without a stream of screenshots. Waits until a region of the screen, a window or the camera changes, goes still or shows some text, and prints one line with a small crop; reads text on the device; compares with a reference. CLI; macOS 14+ (Apple's capture and text recognition frameworks); on Linux, the camera only (V4L2). |
| [headsound](headsound/) | Audio checks and repairs in one line per answer: loudness, loudness range and true peak; clicks, clipping, dropouts, hum, "p" pops, harsh s, DC offset and phase, marked for GoldWave, Audition, Reaper, Audacity or DaVinci Resolve, or as subtitles; what is heard when (on the Mac); declick, dehum, cut pauses, trim, normalize, convert; and on the Mac, record from the microphone until you stop talking. CLI; macOS 14+, Linux and Windows (WAV only, no microphone or sound classifier off the Mac, so far). |
| [headdesk](headdesk/) | A headless desktop for agents: its own Wayland display server, with no monitor and no GPU. Lists windows, takes pictures of the desktop or of one window, clicks and types without permission prompts, waits until apps have stopped drawing and says what area changed, freezes apps and lets single frames through. With `--sandbox`, apps run in a box of Linux namespaces: they read the system, write only into the box, and what they changed can be listed, snapshotted and thrown away. A run can be recorded (pictures, inputs, log, a page to look at them) and its inputs replayed; a frozen desktop draws only when stepped, on a clock that counts frames. Where apps describe themselves (AT-SPI), buttons and fields can be found, clicked and filled by name. One process per desktop, about 9 MB at 1280x800: 300 ran at once on one machine. CLI; Linux. 0.1.0 is an experiment: its tests use its own test client, and GTK 4, Qt 6, Chrome and Firefox have each been started on it by hand and opened a menu. |
| [llmcheck](llmcheck/) | Checks a served language model through its OpenAI-style API (vLLM, llama.cpp, Ollama, gateways): whether the interface does what it accepts (output formats, tool calls, context length, limits, seeds, the key), whether token probabilities match a reference server or a recording of one, speed, and a one-line probe for cron. CLI; macOS, Linux and Windows. 0.1.0 is tested only against its own stand-in server, not yet against a real model server. |
| [keygate](keygate/) | Lets an agent use API keys it never sees: the agent gets a placeholder and a local URL; keygate keeps the key in the system's keychain, checks each request against your rules (host, method, path prefix, expiry), adds the key on the way out, masks it in what comes back, and logs every request. A weaker `run` mode puts a key in one command's environment and masks its output. CLI; macOS, Linux and Windows. 0.1.0 is tested by its own tests and by hand over https with a dummy key; the Windows store has only been compiled. |
| [canmcp](canmcp/) | A car's CAN bus as named, read-only tools for an agent. A profile maps signals from DBC files to readings such as speed, gear and doors, and the agent can wait for a condition (`speed > 30`). The default build contains no code that transmits. MCP server; Linux (SocketCAN). 0.1.0 is tested on a minute each of a real Tesla Model 3 and Hyundai Ioniq 5, replayed onto virtual CAN, not on a car. |
| [homemcp](homemcp/) | A smart home as allowlisted tools for an agent, through Zigbee2MQTT or Home Assistant. Each device has its own allowlist and limits. Locks, alarms and valves answer only to a tool that the client asks a person about every time. Every action is read back, and every attempt is logged, refused ones too. Changes and who is home reach the agent as they happen, `discover` writes the device list from Home Assistant with safe defaults, `announce` says a short message on the speakers you allow, smoke and CO alarms are watched only, never acted on, and doorbells push each ring. MCP server; macOS, Linux and Windows. 0.2.0 is tested against its own stand-in hub, not yet in a real home. |
| [carcloud](carcloud/) | A car through the carmaker's cloud (Smartcar, or a Tesla through Tesla's Fleet API), as a few named commands for an agent: charging, a charge limit within a range, lock; with a Tesla, climate within a temperature range and seat heating, signed through Tesla's own proxy. Commands are capped per day, and unlocking is a tool of its own, off by default. MCP server; macOS, Linux and Windows. 0.1.0 is written from Smartcar's and Tesla's documentation and tested against stand-ins, not yet against either or a car. |
| [mailmcp](mailmcp/) | Mailboxes as tools for an agent, through IMAP and SMTP over TLS. A mailbox made for the agent reads, drafts and sends from its own address; the owner's is read without marking anything and gets drafts, and nothing sends from it, deletes, moves or flags its mail. Text, attachments listed (not read), Polish and other charsets, and a guess at bills (amount, due date), deliveries, travel and invitations; new mail pushed with IMAP IDLE. MCP server; macOS, Linux and Windows. 0.1.0 is tested against its own stand-in IMAP and SMTP server, not yet against a real one. |
| [calmcp](calmcp/) | Your calendars as a few named tools for an agent, over CalDAV: iCloud, Fastmail, Nextcloud, and Google with an OAuth token. Reads the day in your time zone with recurring events expanded, and free time. Creates, moves and cancels events and answers invitations only in the calendars its file allows; each change names the event as the calendar has it, is sent only if the event hasn't changed meanwhile, and is read back; a field a tool doesn't take is refused, never ignored. MCP server; macOS, Linux and Windows. 0.1.0 is tested against its own stand-in CalDAV server, not yet against a real one. |
| [paymcp](paymcp/) | What your customers should be paying and are not, and what they owe that is late, found in a Stripe Billing account by fixed rules: discounts with no end, subscriptions that cost nothing, prices no longer sold, collection paused, invoices never sent or charged or written off, invoices past due, payments that failed, and, with your own file of who has what, more seats or a higher plan than paid for, accounts that use the product without paying, and use never reported. Each finding has an amount, the rows it rests on and what is proposed. It keeps its own record, so a report says what is new and what is no longer found, and "it is meant to be so" is an answer kept with your reason. It also reads card disputes (those to answer, with their last day, come first) and drafts what it can: a message to the customer where a change is theirs to see, and a dispute's evidence as far as the account shows it; nothing is sent. Only reads the account, with a key that can only read, unless you turn changes on and give it a second key: then it does one thing a finding names at a time (end a discount, set a quantity, move a price, resume collection, finalise or resend an invoice, keep evidence unsent), from now on only, read back afterwards. With harness the findings are one page, the Money app. For the money going out, the payment-run check reads a batch of payments to suppliers from the file you export, before you pay it (bank details changed, a supplier never paid before, a likely duplicate, an amount out of line, two suppliers on one account), refuses to note as paid a batch altered after its check, and searches past payments for ones made twice; files only, no key. MCP server and a command-line report; Linux and Windows (macOS not yet tried). 0.4.0 is tested against its own stand-in and was run against Stripe on a made-up business in a test account, reading and changing; never on a live account, and the payment-run check on made-up files only. |
| [harness](harness/) | A personal agent you talk to in Telegram or the terminal: research, a morning brief from your feeds and searches, scheduled tasks, and memory ranked by how often and how recently you bring things up. Every tool call passes one gate (rules, approvals as buttons, grants that expire, `/stop`) and goes into a hash-chained log. As a home butler (with homemcp, carcloud, mailmcp and calmcp): routines asked with one tap, emergencies, the diary, away mode and trips, the door, errands and upkeep, medication reminders, habits suggested, the car warmed, the evening. Models only through omnigate. CLI; macOS, Linux and Windows. 0.1.0 is tested by its own tests and an end-to-end script against stand-in services; not yet run against a real omnigate or Telegram bot. |

## Install

Download a binary for Linux (x86_64, arm64) or macOS (Apple Silicon; headsight on Linux watches cameras only, headdesk is Linux only) from [Releases](https://github.com/Legatia/zigworks/releases), or build from source below (canmcp, homemcp, carcloud, mailmcp, calmcp and paymcp: from source only, so far). All but headsight also come as a zip for Windows (x86_64). Linux binaries are static and run on any distribution.

`site/` is the project page at https://zig.legatia.solutions (static HTML, no build step).

## Building

Zig 0.17.1:

```sh
cd trigrep && zig build -Doptimize=ReleaseFast && zig build test
```

Binaries go to `zig-out/bin/` in each project. CI runs `zig build test` for every project on Linux and macOS (headdesk on Linux x86_64 and arm64 only, canmcp on Linux x86_64 only; homemcp, carcloud, mailmcp and calmcp on Linux and Windows, checked on a Mac by hand; paymcp on Linux and Windows, not yet run on a Mac), and for all but headsight, headdesk and canmcp on Windows too (on Linux, headsight's camera path is tested against virtual cameras with `headsight/scripts/live-linux.sh`, not in CI).
